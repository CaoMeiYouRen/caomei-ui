## 3. 阶段组合建议（三选一）

### 组合 X：「质量可信 + 对外可用」（建议优先）

- **阶段目标**：让下游在接入前能信任质量门与文档——质量门覆盖全、失败可复现、文档中英与响应式无硬伤。
- **主线（4 条）**：① T1 测试可信度（覆盖率门禁 + flaky 治理）；② T1 门禁补强（a11y 回归 + 文档 / 守卫类 + E2E 入门禁）；③ T2 文档对外可用性（README.en-US + en-US 768 溢出 + 翻译旧目录守卫 + 英文同步治理）；④ T4 样板块级守卫（scoped 变量 / 档位死声明 / 字面量回流）。
- **规模**：M~L；**风险**：低—中（唯一不确定项是 flaky 根因定位，可先交付「隔离 + 结论」）。
- **非目标**：不改组件公开 API、不做构建形态改造、不做文档站观感。
- **理由**：零外部依赖、可独立闭环、直接服务「下游敢不敢接入」；且为后续所有改动提供可信回归网。

### 组合 Y：「组件能力 + 体积优化」

- **阶段目标**：补齐下游迁移中已实测到的能力缺口，并把样式体积按需化。
- **主线（4 条）**：① T4 CSS 分层拆分（POC 先行）；② T3 选择类增强（Select 分组 + Tag / Badge）；③ T3 导航与浮层增强（DropdownMenu `model` 嵌套 + 分组按钮 a11y）；④ T3 视觉一致性（token 配对 + 对比度遗留项）。
- **规模**：M~L；**风险**：中（含一次产物结构变更与多处组件契约扩展）。
- **非目标**：不动质量门与文档治理；不做逐组件样式入口（已裁定）。
- **理由**：收益直接可见（体积 + 能力面），但**须先完成用量取证**（当前 momei 侧尚未反馈新用量）。

### 组合 Z：「文档站与对外展示」

- **阶段目标**：把文档站做成可对外发布的正式门面（含版本化）。
- **主线（3 条）**：① 文档站观感与展示力（画廊 / demo 外壳）；② 文档站版本化；③ T2 其余治理项（锚点 / 侧栏不变式、英文同步、README.en-US）。
- **规模**：M；**风险**：中（观感类验收口径需先定义，版本化选型未定）。
- **非目标**：不动组件源码与构建。
- **理由**：观感类候选此前被用户明确「待专项评估」，本组合即该专项；但优先级取决于对外展示的实际诉求。

## 4. 容量、排序与准入边界

- **容量**：三组合均为 3–4 条主线，符合 [规划规范 §6](../../standards/planning.md) 的 3–6 条要求；每条主线须在登记时补齐「执行范围 / 非目标 / 最小验收标准」。
- **顺序依赖**：CSS 分层拆分必须先交付构建路径 POC；依赖闭包类拆分（select / button / input / calendar 家族）须等批次 2 结论后再定。
- **不纳入本阶段的项**：Phase 8（须单独评估且无已接入下游）、momei 侧迁移（外部执行）、RTL、`useDialog`、语言矩阵长期、@iconify/vue / Tailwind preset / Storybook（均为条件触发或已决定不做）。
- **决策落定后的动作**：按 [规划规范 §3.8](../../standards/planning.md) 同步全部受影响载体——分配阶段编号 → 登记 `todo.md` 当前阶段 → `roadmap.md` 阶段表与状态行 → `backlog.md` 标注迁出（`→ Mx（阶段 …）`）→ 长期任务触发义务检查。

> **M2-1 门槛定义（本阶段，可复验）**：候选须**同时**满足 ① **有下游实测用量 ≥ 1 处**——给出可复现命令与快照日期（如 `rg -n "<模式>" <下游仓库> | wc -l`，命中 0 处即不达标）；② **不引入未登记的对外契约变更**——新增 props 须走受控枚举并登记[设计规范 §7](../design-spec.md)。两条均满足者提交用户确认后纳入实施；任一条不满足者留 [Backlog](../../plan/backlog.md) 原行并附判定结论。
