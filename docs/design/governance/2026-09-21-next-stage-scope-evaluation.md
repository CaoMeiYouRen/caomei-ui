## 4. 阶段组合建议（三选一）

### 组合 P：「发布就绪与对外门面」（建议优先）

- **阶段目标**：让库「能装上、装得对、查得到」——收敛发布链路与 main 的包形态分叉，并把文档站做成可对外引用的正式门面。
- **主线（4 条）**：① T1 发布链路（CI 自动发布启用 + 凭据方式决策 + runbook 同步）；② T1 版本发布（含 M1-3 破坏性包形态 + 发布后校验）；③ T1 文档站版本化；④ T3 文档对外可用性（锚点 / 侧栏不变式 + 英文同步治理 + nav / sidebar 链接校验）。
- **规模**：M~L；**风险**：中（凭据为外部输入；首个破坏性形态版本）。
- **非目标**：不改组件公开 API、不做 a11y / E2E / 视觉门禁、不做样式收敛、不做文档站观感美化。
- **理由**：零内部阻塞、可直接闭环；分叉已持续一个阶段，越晚收敛下游接入口径越乱；文档站版本化依赖版本基线，正好接上发布动作。

### 组合 Q：「工程可信度补全」

- **阶段目标**：把回归网从「单测 + 覆盖率」扩到 a11y、E2E 与视觉面，使改动「敢发」。
- **主线（4 条）**：① T2 a11y 回归；② T2 E2E 规格与门禁；③ T2 视觉回归基线；④ T2 flaky 治理 + 等价验证产物入库。
- **规模**：M~L；**风险**：中（flaky 根因不确定、E2E 流水线成本）。
- **非目标**：不动发布链路与文档站、不做样式收敛。
- **理由**：Phase 11 已把覆盖率接入周期回归与 release，可信度缺口集中在 a11y / E2E / 视觉；完全无外部依赖。

### 组合 R：「一致性收官与治理守卫」

- **阶段目标**：清零已登记的规范偏差与治理守卫存量，为后续改动提供无回声的基线。
- **主线（4 条）**：① T4 尺寸档位 `:where()` 收敛 + 重复声明守卫；② T4 实底 token 配对 + 对比度遗留；③ T6 治理守卫精选；④ T4 触发器 `unstyled` 收敛 + T3 文档站残余（hydration / demo 动画 / 外链图片）。
- **规模**：M；**风险**：中（含视觉变更与改色裁定）。
- **非目标**：不开新能力、不动发布链路与门禁体系。
- **理由**：低成本高确定性，但**价值偏内部**；其中 28 条归一化与对比度改色均需用户先裁定。
