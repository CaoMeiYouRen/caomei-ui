## 5. 建议主线与原子条目（草案，待用户裁定）

### M1 a11y 例外处置与受检面扩面（**必选**）

- **执行范围**：① 修复可按规范清零的例外——`CaomeiCalendar` 根容器 `aria-label` 落点、`CaomeiMultiSelect` 关闭态空 `aria-controls`、`CaomeiStepper` 悬空 `aria-describedby`；② `CaomeiToastProvider` 焦点哨兵例外按 D2 裁定处置（上游反馈 / axe 定向豁免 / 维持并记录）；③ 受检面扩面——12 个面板内导出的**展开态**与 DataTable **折叠分组 toggle** 纳入 axe 受检面。
- **非目标**：不改造 Reka primitive；不为扩面而扩面（时序敏感项须先确定稳定驱动方式，否则维持登记并给出触发点）；不改组件视觉。
- **最小验收标准**：① 修复项落地后**例外清单同步收窄**（`count` 指纹更新、条目删除须有等价新增断言）；② `pnpm test:a11y` 例外外零违规；③ 扩面项带穷尽性机检（受检面集合与 `caomeiComponents` 的差集有据、非静默豁免）；④ 涉及引用型 ARIA 属性的判定以**真实 Chromium** 复验（happy-dom 与浏览器取值差异已有先例）。
- **依赖**：D2（例外处置取向）、D3（扩面取舍）。

### M2 样式与 token 一致性收口（**必选**）

- **执行范围**：① 字段 shell 样式层共享（13 条声明 × 4 组件，形态按 D4 裁定）；② 实底前景 token 配对复核（枚举 `-solid` 实底与自适应底的配对消费点，按 D6 裁定修复）；③ 对比度遗留项盘点与处置（按 D5 裁定改色或接受并登记）；④ 触发器 `disabled` 透传与包装层归一化；⑤ 一致性机检子项——样式侧旧命名裸类守卫、`check-design` 声明解析健壮性、直连 Reka 触发器守卫（按 D8 取舍）。
- **非目标**：不做与一致性无关的样式重构；不改动「有意分级」的既有视觉（除非 D5 明确授权）。
