### 4.1 各主线执行口径

- **M1 下游迁移护航与反馈闭环**

- **M2 对比度与配色口径裁定收口**
  - 执行范围：对 4 项库内缺口（soft primary 亮 **4.37:1** / toast 中性强调描边暗 **2.31:1** / caomei 预设 danger **3.76:1**·soft **3.23:1** / caomei 预设 primary-solid **4.17:1**）逐条裁定——**修色**或**维持 + 理由**；统一裁定 C1 / C2；C20 是否随批。
  - 非目标：**不以「全部改成达标」为默认动作**（preset 品牌色过去两次经用户裁定保持不变）；不改 Reka primitive；不扩大为全库配色重构。
  - 最小验收：每条裁定可追溯（复算值 + 阈值 + 结论 + 若修色的前后值）；若修色，`capture:styles` 差异**逐项有据**（接受项须显式登记）；对比度复算命令可复现；**载体行在 `backlog.md` 或阶段条目中真实存在**（修复 C50 的载体缺失）。

  - 非目标：不做与守卫无关的治理重构；不为存量缺工件做「历史纠错」（如实登记即可）。
  - 最小验收：新增守卫进入 `verify` 常驻链（或显式声明仅告警）；`.gitignore` / README 口径一致；`pnpm governance:check` 全绿。

  - 执行范围：C49 根因定位并修，或显式判定「环境限制」并调整用例预算（须给出连续多轮全量零失败证据）；补 C36（C40 按容量）。
  - 非目标：不为覆盖率数字补测；不做与稳定性无关的测试重构。
  - 最小验收：连续 ≥5 次全量测试零失败（或明确的预算调整 + 复核依据）；新增常驻用例不得引入 flaky。
- **M5 交付节奏（发布 0.4.0）**
