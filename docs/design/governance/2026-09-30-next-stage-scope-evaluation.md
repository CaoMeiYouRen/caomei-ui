### 4.1 各主线执行口径

- **M1 组件能力与主题预设落地**
  - 执行范围：新增具名「极简」预设（`minimal` / `default`，名称由 D2 定）与 `[data-preset]` 激活，**缺省路径逐值不变**（`capture:styles` 0 差异口径）；回扫并同步全部 claim 载体（`AGENTS.md §4` / README 中英 / 开发规范 §6 / 设计规范 §4 / 主题与样式设计）；C7 按 D9 落地；C5 补组件页说明。
  - 非目标：不引入 Tailwind / UnoCSS；不做破坏性 API 变更；不改变既有 caomei / momei 预设的色值；C10 / C11 未获 D5 授权则不启动。
  - 最小验收：缺省渲染零漂移（基线 0 差异）；预设切换中英文档齐备；claim 载体全部同步（无并存旧口径）；若涉及渲染走 `@ui-validator`；`pnpm verify` exit 0。
- **M2 组件设计一致性回归扩展**
  - 执行范围：先出**评估**——把 [设计规范 §6](../design-spec.md) 组件约定表逐条按「可机检性」分级（声明层 / 计算样式层 / 几何层 / 交互层 / 仅人工），标注现有装置覆盖与缺口；再按容量把**可机检项**落为单测 / E2E（含负向对照）。
  - 非目标：不为覆盖率数字补测；不引入高误报的启发式；不可机检项不强行机检（显式登记为人工验收项）。
  - 最小验收：评估记录逐条有落点与判定；新增断言具负向对照（构造违规 → 失败）；不引入 flaky。
- **M3 对比度与配色口径终局裁定**
  - 执行范围：对 6 项在册缺口逐条裁定——**修色**或**维持 + 理由**；若修色，差异**逐项有据**（接受项须显式登记）并重冻结基线。
  - 非目标：**不以「全部改成达标」为默认动作**（预设品牌色经用户两次裁定保持不变）；不改 Reka primitive；不扩大为全库配色重构。
  - 最小验收：每条裁定可追溯（复算值 + 阈值 + 结论 + 若修色的前后值）；复算命令可复现；载体行在 `backlog.md` 或阶段条目中真实存在。
- **M4 质量装置补口与消缺**
  - 执行范围：C19 / C20 新增守卫（正反例语料 + 抗静默收窄 + 负向对照），明确接入 `governance:check` 还是仅告警；C31 / C45 同步版本策略页正文并评估弱守卫边界；C18 扩采样 fixture（须区分「组件契约承载」与「夹具固有值」，口径见 `.session/wisdom.md` 的计算样式采样条目）。
  - 非目标：不做与守卫无关的治理重构；不为存量缺工件做历史纠错；不为凑采样项采夹具固有尺寸。
  - 最小验收：新增守卫进入 `verify` 常驻链（或显式声明仅告警）；`pnpm governance:check` 全绿；采样扩展后基线复跑 0 差异。
- **M5 下游升级护航与兼容性回归**
  - 执行范围：产出 0.4.0 升级护航资产（版本差异清单 / 回归关注点 / 升级指引），供 dependfix / momei 消费；若 D6 授权则出 Phase 8 范围评估（清单 + 跨仓库 CI 触发形态），**评估不等于启动**。
  - 非目标：不为下游做他仓迁移实施；不修改下游仓库；不建立跨仓 CI 触发实体（除非 D6 授权）。
  - 最小验收：护航资产逐条回链发布记录与备份差异来源；Phase 8 评估给出触发形态与容量边界。
- **M6 交付节奏（发布 0.5.0）**
  - 执行范围：版本基线 + CHANGELOG + tag + `npm publish`（**本地手动**，沿用既有口径）+ 发布后校验 + 文档版本句同步 + 发布前长期任务门槛复核留痕 + C39（若取）。
  - 非目标：**不启用 CI 自动发布**；不夹带未验收的能力变更。
  - 最小验收：registry 产物校验与发布日志一致、四项子路径冒烟 + 消费方构建通过、发布后 `pnpm verify` 复跑 exit 0、版本展示面机械校验全绿。
