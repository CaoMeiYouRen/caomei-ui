> 创建时间：2026-10-15

## 2. 组件与 API

| 组件 | 关键属性 | 说明 |
|:---|:---|:---|
| `CaomeiAlert` | `tone`（默认 `neutral`）、`variant`（`soft` 默认 / `solid` / `outline`）、`title`、`description`、`icon`（默认 `true`）、`closable`、`closeLabel` | 薄预设包装；根节点同时带 `caomei-alert` 与 `caomei-message*` 类 |
| 插槽 | `default`（描述）、`icon`、`actions` | 无 `title` 插槽（与 `CaomeiMessage` 一致，标题走 prop） |
| 事件 | `close` | 由 `CaomeiMessage` 转发 |

- **不承载自有样式**：无 `<style>` 块、无 `--caomei-alert-*` 钩子——外观、token 与 `--caomei-message-*` 覆盖钩子全部复用；`caomei-alert` 类名只作定位钩子（组件页已明示）。
- **`variant` 不含 `simple`**：行内无框形态属字段级校验场景，由 `CaomeiMessage` 承载。
- **`size` 显式过滤**：`CaomeiMessage` 的 `size` 不在 Alert 的收敛 API 内，若无过滤会经 `$attrs` 静默透传（类型上不可表达、运行时却生效）；`alert.vue` 用 `useAttrs()` 过滤该键，组件页同步声明处置方式，并有单测锚定。

## 3. 实现要点

1. **静态档（本批唯一的语义新增）**：`CaomeiMessage` 的 `MessageRole` 增加 `'none'`——渲染时**不输出 `role`**（`role === 'none' ? undefined : role`），即不进 live region；`CaomeiAlert` 固定取该档。取舍理由（组件页已逐条声明）：常驻内容在页面加载时即存在于文档序，读屏器按序可读，本就无需 live region；而 live region 会在**建立时与内容变更时**播报——常驻提示既无「新插入」语义，其文本变更也更适合由页面按上下文播报。（措辞按 R1 建议去掉了「重渲染必然重复播报」这类绝对化断言。）`role` 只应授予「由交互 / 异步结果**新插入**」的内容（= `CaomeiMessage` / `CaomeiToast` 的场景）。**与 Element Plus `el-alert` 恒 `role=\"alert\"` 的差异已入迁移表。**
2. **分工逐条化**：组件页给出「场景 → 选用 → 是否播报」表与「Alert / Message / Toast」四轴对照表（语义、live region、位置、生命周期、变体、服务式调用）。
3. **口径冲突消除（三处同批更正）**：
   - `docs/design/components.md` §3（Tier 1）行：`Message / Alert` 的实现方式补「`Alert` 是 `Message` 的语义预设包装，与本体共用同一外观层与 token」；
   - `docs/components/message.md`（中英）+ 中英总览页：原「单组件同时承载 Message / Alert 语义」→ 更正为「提示条承载 live region 播报；内联常驻提示用 Alert」；
   - `docs/design/design-spec.md` §2 组件样式表 + §7 迁移条目：补记 Alert 的预设关系与 `role` / `simple` 差异。
   更正依据 = **组件目录 / 设计规范 / 组件页三处权威载体**原即把二者记为同一实现，而范围评估（2026-10-13）与 `todo.md` 记为缺口；本批按用户裁定取「一套外观 + 两个导出」的统一口径。
4. **非破坏性**：`MessageRole` 为新增枚举值（默认仍 `status`）；soft 底色由字面量 `8%` 改为 `var(--caomei-message-soft-mix, 8%)`（默认值不变）。

## 5. 验证与判别力

### 5.1 对比度复核（本批核心验收项）

新增装置 `test/e2e/alert-contrast.e2e.ts`（真实 Chromium）：

- **受检面**：夹具末尾 `#alert-contrast` 段 **5 色调 × 3 变体 = 15 条**（下界断言防清单被静默收窄），亮色与暗色（`data-theme=\"dark\"`）各测一遍；
- **判据**：WCAG 2.x 相对亮度，正文阈值 **4.5:1**；
- **口径要点（决定装置是否可信）**：`soft` 底色是 `color-mix()` 的**半透明**值，必须与页面实际底色**逐层合成**后判定——只读元素自身 `background-color` 会把透明底当黑/白，得出与真实渲染无关的结论。装置自根向下逐层合成（`html → … → 元素`），文本色同样按 alpha 合成后再算比值。
- **颜色归一化**：`color-mix()` 的计算值在 Chromium 中序列化为 `color(srgb r g b / a)`，而 canvas `fillStyle` **不接受**该形态且会静默保留上一次赋值（首版即因此把全部 soft 底读成「8% 黑」）——装置对该形态单独解析，并给 canvas 路径加「哨兵值比对」以防再次静默回退。
- **实测结果（装置即证据）**：
  - **修复前**：`neutral/soft` **4.38**、`danger/soft` **4.27** 低于 4.5（其余 13 组合达标）——这是既有 `CaomeiMessage` 的既有缺陷，且与源码注释「其余 tone 只升不降」的声称不符；
  - **修复后**：亮色 / 暗色 **30 个组合全部 ≥ 4.5**，装置转绿。
- **同批修复**：`Message` 的 soft 底色改为 `var(--caomei-message-soft-mix, 4%)`（**统一**取 4%，不再按 tone 分档）；同步更正源码注释为**实测口径**（判据 + 裕度 + 复跑要求）。
- **裕度（R1 追问后的收口）**：分档方案下 `success` / `warning` 在 8% 时仅高出阈值 **0.0068 / 0.0064**（贴线，任何微调即翻档），故改为统一 4%——实测最低 **4.543**（亮色）/ **≥4.55**（暗色）；装置另设**最小裕度 0.04**（可拦下 8% 旧配置的 0.0068，同时不超出 tone 语义色本身的天花板——`neutral` / `danger` 对白底为 4.83，理论上限裕度约 0.33）。
- **判定精度**：装置改为**未舍入值**参与判定（`Math.round` 仅用于展示）——先舍入再比较会把真实 4.495–4.4999 放行。
- **连带装置同步**：soft 底色属计算样式采样项 ⇒ **重冻结** `test/capture/baseline.json`（313 项；终态为 **5 个 `variant.message.<tone>.soft` 的底色 alpha `0.08 → 0.04`** + 采集时间戳，与 R1 时的分档中间态不同——见 §9 的 RG-S1 收口说明），复跑 `capture:styles` **0 差异**。
- **静态档的真实浏览器断言**：同装置断言 `#alert-contrast` 段内 `role=\"status\"` / `role=\"alert\"` / `aria-live` 命中数为 **0**（静态档在真实渲染中确实不进 live region）。

## 8. 边界（显式声明）

1. **Alert 无自有外观与覆盖钩子**：需要 Alert 专属 token 的场景由使用方经 `--caomei-message-*` 覆盖或用 `caomei-alert` 类名定位；**不提供**第二套皮肤（用户裁定）。
2. **不提供 `simple` 行内形态与 `#title` 插槽**（与 `CaomeiMessage` 对齐）。
3. **不提供 `role` / `live` 开关**：Alert 固定静态档；需要播报的反馈场景改用 `CaomeiMessage` / `CaomeiToast`（避免「Alert + role」两套语义并存）。
4. **soft 底色档按 tone 分档**（`neutral` / `danger` 取 4%，其余 8%）：若后续统一调整，须同步复跑对比度装置并重冻结计算样式基线。
5. **对比度装置只覆盖注入口径的「文本 / 合成背景」**：不覆盖图标描边、边框与 `solid` 变体下 `on-solid` 与其它语义色的组合（未在本受检面内）。
6. **未覆盖**：`simple` 变体与 `size` 档（`sm` / `lg`）的字号-对比关系——`CaomeiAlert` 直接渲染 `CaomeiMessage`，其 `soft` / `solid` / `outline` 的计算样式与 `Message` 同源同值，故这三档（含暗色）已在受检面内；另未覆盖**图标描边与边框**的非文本 3:1 判据。
