# Phase 25 M2-2：触摸目标命中区实测复核

> 阶段 / 条目：Phase 25 M2-2（移动端与响应式优化——触摸目标复核，用户裁定**本轮只出实测清单与提升建议**、不改样式）。
> 验收口径依据：[Phase 25 登记批次记录](./2026-10-16-phase25-registration.md) §2（「逐组件实测命中区尺寸并留痕；结论落文档；若提升则同步样式与视觉基线」）。
> 关联：[响应式设计](../../design/responsive.md) §3 矩阵 #16 / §5 决策 ①、[Backlog §1.5](../../plan/backlog.md)、`test/a11y/rules.ts` 的 `target-size` 禁用理由。

## 1. 背景与触发

矩阵 #16「触摸目标」自 2026-09-16 起为**已决策 ①「暂不提升」**（Checkbox / RadioButton 18px、Switch 40px、`control-height-sm` 28px），当时**未留下逐组件实测读数**。本条目的作用是把该决策补成**带实测依据的清单**，并给出提升建议及其影响面，供后续裁定。

同时存在一处装置缺口：组件级 a11y 审计运行在 happy-dom（无布局引擎）下，`target-size` 规则**被禁用**（理由「触摸目标尺寸依赖布局与视口」，见 `test/a11y/rules.ts`），因此命中区在真实渲染下**此前无任何常驻读数**。

## 2. 实测方法（可复现口径）

- **被测面**：E2E 主夹具（`test/e2e/fixtures/app.vue`）——与响应式用例同一被测面，覆盖库内绝大多数交互组件的**规范用法**；浮层类在 `#overlay-in-dialog` 的模态内打开后测量其面板项（共 7 类：Select / MultiSelect / AutoComplete / DropdownMenu / ColorPicker / DatePicker / Popover；Popover 面板在夹具中无交互子项 ⇒ 0 行）。
- **视口**：**390×844**（mobile 全量档）与 **320×568**（`mobile-320` 定向档）。
- **目标面（可点目标）**：`button` / `input`（非 `hidden`）/ `select` / `textarea` / `a[href]` / `summary` 与 `role ∈ {button, checkbox, radio, switch, slider, tab, menuitem, menuitemcheckbox, menuitemradio, option, link}`。**容器型角色不计入**（`tabpanel` / `radiogroup` / `tablist` / `menubar` / `dialog` / `listbox` 等），避免把容器尺寸读成命中区。
- **命中区定义**：目标元件盒与其**关联标签**盒（`label[for]` 或最近祖先 `label`）的**并集**。
- **达标判据**：两轴取小边。`≥44px`（Apple HIG，本仓决策 ① 的讨论基线）/ `≥24px`（WCAG 2.5.8 Target Size (Minimum) AA）。
- **两档差异（如实登记）**：390 档受检 **293** 行；320 档 **291** 行——差异 2 行来自 320 档 **DropdownMenu 面板未取到读数**（触发器点击超时，脚本记入 `observations`）；**低于 24 的行数两档同为 87**，中段 193 → 191（即缺失的 2 行属中段）。
- **取证工件（gitignored，供复现）**：`test-results/phase25-m2-2/measure-hit-areas.mjs` + `hit-areas-390.json` / `hit-areas-320.json`；复算命令 `node test-results/phase25-m2-2/measure-hit-areas.mjs 390 320`（需夹具服务在上述端口）。

## 4. 结论与提升建议（**本批不改样式**）

**结论（按 §3 的实测分布，非定性表述）**：

1. **两轴达标情况**：289 个目标中 **≥44×44 者仅 9 个**（FileUpload 拖拽按钮 ×3、Stepper ×3、Textarea ×3）；**24 ~ 43.99 者 193 个**；**< 24×24 者 87 个（30.1%）**——即「WCAG 2.5.8 达标」为**多数但非绝大多数**：约三成目标在最小尺寸判据下不达标。
2. **不达标的集中面**（§3.1）：① **清除 / 关闭类 icon 按钮 `13.33×13.33` 共 34 个**（TagsInput / AutoComplete / MultiSelect 的每个值片各一 + Password / Tag），是 87 个的**最大单一构成**；② **字段族内联输入行 `×16` 共 22 个**（`input` / `textarea` 内联行）；③ 表单控件盒（Checkbox `18×18`、RadioButton 高 18、Switch `40×22`、Slider / ColorPicker 滑柄 `18×18`）；④ 行高受限项（Breadcrumb 高 18、DataTable 排序高 18、Message 关闭 `17.33`、Select 清除宽 20、MultiSelect 值片 `29.33×19.33`）。
3. **与既有决策 ① 的关系**：决策 ① 的四个对象（Checkbox 18 / RadioButton 18 / Switch 40×22 / `control-height-sm` 28）**全部在实测中复现**；既有「维持」结论**与本次读数不冲突**（本批按用户裁定不改样式）。
4. **阈值口径提示**：若以 **Apple HIG 的 ≥44** 为基线，影响面覆盖**全库交互面**（Button `md` 36、字段族 32 ~ 36、Menu 24、Calendar 27.13、Accordion 43.59 等均在 24–44 带内）；若以 **WCAG 2.5.8 的 ≥24** 为基线，需处置的是 §3.1 的 **87 个目标 / 15 个组件面**。

**提升建议（分级，供后续裁定；若采纳须按 §5 影响面同步）**：

| 级别 | 对象（含实测规模） | 建议形态 | 影响面 |
|:---|:---|:---|:---|
| **P0** | §3.1 的 **`13.33×13.33` 清除 / 关闭 icon 按钮（34 个，涉 5 组件）** + Message 关闭（1 个） | **不可见命中区原语**：`::after`（绝对定位、负 `inset`）把命中区扩到 ≥24×24，**不改视觉盒** ⇒ 布局与视觉基线零变化 | 仅命中区语义；需配套常驻命中区用例（受检面下界 + 负向对照） |
| **P1** | 表单控件盒：Checkbox（2）、RadioButton（6）、Switch（2）、Slider（3）、ColorPicker 滑柄（4） | 同原语扩到 ≥24×24；Checkbox / RadioButton 已有「关联标签并集」承接宽度，**缺的只是高度** | 同上；Switch 需避免 `::after` 影响轨道绘制 |
| **P2** | 行高受限与内联行：字段族内联输入行（22）、Breadcrumb（2）、DataTable 排序（3）、Select 清除（1）、MultiSelect 值片（5）、值片内 icon（2） | **逐项评估**（不可一律按「容器即命中区」推定）：① 字段族中**仅部分组件**（MultiSelect / AutoComplete 的 anchor）在容器上绑定了点击聚焦，普通 Input 根**无** `@click`，故内联行的命中区不能默认由容器承接；② Breadcrumb / DataTable 排序的**行高**提升会改视觉（需重冻结 `test:visual` 基线） | 若改行高则触及视觉基线；内联行须按组件逐个确认交互绑定后再定 |
| **维持** | §3.2 / §3.3 全部 | 维持现状 | — |

**装置建议（与本条目的实测同批登记，不占条目）**：① `test/a11y/rules.ts` 的 `target-size` 禁用理由**已补**指向本记录（本环境无布局引擎 ⇒ 真实渲染读数由该装置承担）；② 若后续采纳提升，应把本批的 gitignored 取证脚本**提升为常驻装置**（命中区用例 + 受检面下界 + 负向对照），使「命中区不回退」进入门禁。
