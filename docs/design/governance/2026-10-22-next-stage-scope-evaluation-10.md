### A 冻结面终审与 1.x 承诺落地（4 条）

- **A-1 冻结面清单终审与 1.0 决策记录**
  - 面：组件公开 props / events / slots 的名称与语义；`exports` **13 键**逐键语义；包根公开导出名；`--caomei-*` token 的名称与用途；**10** 语 locale 命名空间与「预注册 + 按需注册」形态；`reka-ui` 下 `InputNumber` 的 `step` 语义按 2.10.4 行为冻结。
  - **现状取证**：`node -e "console.log(Object.keys(require('./package.json').exports).length)"` → **13**；`ls src/components | grep -v _shared | wc -l` → **56**；token 定义数 `rg -o --no-filename -- "--caomei-[a-z0-9-]+:" src/styles | sort -u | wc -l` → **68**（全局语义层），全 `src` 同命令 → **146**（含组件作用域覆盖钩子，如 `--caomei-select-max-width`）。**冻结面取「全局 68」还是「全部 146」须在本条目裁定**——两者对下游的承诺强度不同。**陈旧口径**：`docs/guide/version-policy.md` 冻结面写「`exports` 全部 **5** 键」，与 0.7.0 起的实际 13 键矛盾 → 本条目须修正。
  - 验收：清单逐项可复算；例外流程（安全 / 正确性必须破坏时如何走）成文；「最后一破」归零确认（0.7.0 的 locale 形态已发布，不再回改）。

### B 行为收口与准破坏性变更（4 条）

- **B-1 DataTable 行选择全选作用域收口（方案 A，含可访问名）**
  - 行为：`selectionMode="multiple"` 的表头全选只作用于**当前页**；客户端分页下跨页选择保留；表头状态改用 `getIsAllPageRowsSelected` / `getIsSomePageRowsSelected`，切换用 `toggleAllPageRowsSelected`；无分页行为不变；`lazy` 下仍为当前页；受控全表选择由父级写 `selection`，**不新增 prop**。
  - 可访问名：「全选」→「全选当前页」（**10 个 locale**；backlog 行记的「5 个」是 2026-10-17 时点值，0.7.0 起已为 10 语，登记时须同步该行）。`selectAll` / `selectAllScope` 契约**仅登记**，出现真实需求再评估。
  - 验收：分页 × 选择测试；中英文组件页、PrimeVue 迁移差异、CHANGELOG 与 GitHub Release 四处披露。
- **B-2 `lazy` 跨页选择在受控输入与 emit 两侧收敛**（既有缺陷）：`rowSelectionState` 经 `indexOfRow` 查 `props.data`、`onRowSelectionChange` 用 `props.data.filter` 组装，两侧都只保留当前页行。
- **B-3 `rowKey` 缺省按索引在 `lazy` 下可能撞 id**（既有缺陷）：选择 / 展开受影响。
- **B-4 `engines.node` 由 `>=20` 提升到 `>=22`**
  - 现状：`package.json` 为 `>=20`，而 Node 20 已于 **2026-04** EOL；1.0 之后再提升属于破坏性变更。
  - 验收：`engines` 与文档同步；CI 仍用 `lts/*`；在 1.0.0 发布说明中列为**发布前调整**（属准破坏性变更：会排除仍在 Node 20 上的消费方，故必须在 1.0 前完成；1.0 后同类调整须走 major）。

### C 发布链路就绪与 1.0 交付（3 条）

- **C-1 预发布通道与覆盖率前置**
  - 现状：`scripts/release/manual-release.mjs` 的 `VERSION_PATTERN` 接受预发布版本，但 `buildPublishArgs` 只产出 `npm publish`，**无 `--tag`** → 预发布版本会落到 `latest`；`preflight` 只跑 `pnpm verify`，**不含覆盖率**（覆盖率仅在 `release.yml` 与周级回归）。
  - 交付：`--tag` 透传（`next` / `latest`）+ dry-run 与日志同步 + 单测；`preflight` 纳入 `test:coverage` + `check:coverage`（或留等价证据）。
  - 验收：`pnpm release:manual run --version=1.0.0-rc.1 --tag=next --dry-run` 输出正确命令。
- **C-2 1.0.0 CHANGELOG 里程碑段与 GitHub Release note**
  - **现状取证**：`git log --format=%s v0.7.0..10de6e8^ | sed 's/(.*//'` → **11** 个提交（docs 6 / fix 1 / build 2 / chore 1 / test 1）。生成器只收 feat / fix / refactor 等，因此 1.0.0 段**不会为空，但只会出现一条 `fix(release)` 工具修复**，不足以承载里程碑说明。
  - 交付：人工里程碑段（1.x 承诺、冻结面、`engines` 调整、locale 与 DataTable 行为说明）+ 验证 `announce` 能从 CHANGELOG 正确抽取。
- **C-3 1.0 交付执行**
  - 顺序：推送本地 5 个提交（2026-10-22 实测 `origin/master..10de6e8^`）→ `1.0.0-rc.1` 发 `next` → 下游复验（D-1）→ `1.0.0` 发 `latest` → 发布后校验（registry / tarball shasum / 解包 / `exports` 13 键）→ 版本句同步 → GitHub Release。
  - 验收：发布执行记录；registry `latest` = `1.0.0`；`v1.0.0` tag 与 GitHub Release。

## 4. 规模与风险

- **规模**：4 条主线 / **13** 条原子条目（A 4 / B 4 / C 3 / D 2），与 Phase 20 ~ 25 的 8 ~ 16 条同量级；预估 **2 ~ 4 个交付轮**（A-1 / A-2 / A-3 为决策与评估，不产生大改代码）。
- **阶段数**：**1 个阶段**足够；若 D4 选「评估 + 实现」，`Form` 实现另开一个阶段；RTL 与触摸目标各自单独立项，均不进本阶段。
- **风险**：
  1. **冻结面改写面广**：涉及中英 5 类载体，`0.x` 表述回扫须人工逐载体核对（自然语言计数与措辞无机检）。
  2. **B-1 是行为变更**：须四处披露；且必须排在 1.0.0 发布**之前**，否则只能进 2.0。
  3. **rc 依赖 `--tag`**：未先补 C-1 就发 rc，会把预发布版本落到 `latest`（当前脚本缺口已实测）。
  4. **发布顺序不可倒置**：rc → 下游复验 → 1.0.0；先发 1.0.0 再验，等于把不可逆版本当试验品。
  5. **Phase 24 回填属阶段外动作**：并入新阶段条目表会造成归属与编号混乱。
- **非目标（建议）**：RTL / 触摸目标 / 二期语言 / 长尾组件 / `Form` 实现 / 提交驱动自动发布 / `reka-ui` 与 `conventional-changelog` 升级；不做破坏性 API 变更（B-1 为行为变更，非 API 契约变更）；不引入 Tailwind / UnoCSS；不自动推送。
