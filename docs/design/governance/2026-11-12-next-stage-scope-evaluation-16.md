## 2. 主线草案（裁定前草案，符合[规划规范 §6](../../standards/planning.md) 的 3 ~ 6 条容量）

### Option A（推荐）：质量收口 + 发布 1.3.0

- **A-M1 依赖适配与例外收口**：`reka-ui` 2.11.0 适配（#33 合入）、删除 ToastProvider 的 `aria-hidden-focus` 例外、`THIRD-PARTY-LICENSES` 标题同步；验收 = 全量单测 / 相关 E2E / `capture:styles` / `test:visual` 与 Phase 31 评估读数一致。
- **A-M2 文档站质量收口**：`with-select` 示例补可访问名并纳入 a11y 抽检；首页 hydration mismatch 定位并定性（上游 / 本仓），有结论即登记。
- **A-M3 文档站 demo 过渡（按 D2）**：仅在用户选择「恢复」时纳入，逐组件声明并约束 reduce 语义。
- **A-M4 发布 1.3.0（按 D1）**：发布前门槛复核（长期任务第 35 轮）、CHANGELOG / tag / GitHub Release、下游兼容 dispatch 复验；**不改变**发布链配置。
- 规模：3 ~ 4 条主线 / 4 ~ 5 条原子条目。

### Option B：仅质量收口（不发布）

- A-M1 + A-M2（+ A-M3 按 D2），不含发布；版本继续积累。
- 规模：2 ~ 3 条主线 / 3 ~ 4 条原子条目。

### Option C：最小批次（仅依赖适配）

- A-M1 + `deepmerge` 告警判定登记；不含文档站与发布。
- 规模：1 条主线 / 2 条原子条目；适合作为发布前的快速清障。

### Option D：能力扩展（不建议）

- 长尾组件**择一**（Sidebar / ScrollPanel / BackTop / Rating / TimePicker）、国际化二期 / RTL、服务层 `useDialog`、图标 `@iconify/vue` peer。
- 规模：2 ~ 3 条主线 / 4 ~ 6 条原子条目；**触发条件未满足、风险与工作量显著高于本轮候选**。

## 4. 规模与风险

1. **发布不可回滚**：1.3.0 一旦发布即成为 `latest`，需 D1 明确授权；发布前须完成长期任务门槛复核与下游 dispatch 复验。
2. **文档站 hydration**：可能归因为 VitePress 上游行为；若无本仓修复面，按「定性 + 登记」收口，不强行修改主题。
3. **demo 过渡**：恢复后会改变文档站演示观感，且需与系统 reduce 语义并存；默认不纳入（D2 ②）。
4. **`deepmerge` 无补丁**：low 且为传递依赖，override 到未修复版本无意义；默认接受并登记，待上游发布补丁后随依赖升级。
5. **阶段编号**：本记录**不分配编号**；D0 ① 后按「已有最大编号 + 1」分配并同步全部载体。
