## 2. 上游破坏性面逐条核对

| 变更 | 本仓影响 |
|:---|:---|
| `clearMocks` 默认 `true`（等价 `vi.clearAllMocks()`：只清调用历史，不清实现） | 全量套件实跑通过：无用例依赖跨用例的 mock 调用历史；实现泄漏仍须由 `beforeEach` 自理 |
| 未 await 的异步断言判失败 | 全量套件实跑通过：无此类存量用例暴露 |
| `testNamePattern` 分隔符改为 ` > ` | 仓内无 `-t` / `testNamePattern` 用法 |
| inline projects 继承根配置 / 共享 Vite server | 无 `test.projects` |
| 被引用配置可定义嵌套 projects | 无多配置文件项目 |
| `vi.mock` / `vi.hoisted` 仅限顶层 | 无嵌套调用（否则启动即抛错） |
| 类 mock 保留原型 / 浏览器 automock 行为 | 未使用浏览器模式与类 mock |
| benchmark API 重写 | 无 `bench` 用法 |
| 移除 `vitest/coverage` / `reporters` / `environments` / `snapshot` / `runners` / `suite` / `mocker` 入口 | 仓内无相关 import（`@vitest/expect` 亦无直接依赖） |
| 覆盖率 `include` / `exclude` 改为相对匹配 | 配置为 `include: ['src/**']`，实跑文件集覆盖 `src/**`（组件 / composables / nuxt / resolver 均在报表内），无收窄 |
| reporter 产物迁到 `.vitest/`、json / junit 默认写文件 | 仓内无 `--reporter=json` / junit 管道用法 |
| worker id 改为 1 基 / `resolveConfig` 返回值变化 / UI token | 未使用 |

## 4. 边界

1. `clearMocks` 默认值变化属**行为口径变更**：后续新增用例若依赖跨用例 mock 历史会直接失败，属预期收紧；不通过配置回退掩盖。
2. 未启用 `pool: 'vmThreads'` 等性能建议（`happy-dom` 环境创建耗时提示），不属升级验收面，登记为可选优化。
3. **覆盖率阈值不在 vitest 配置内**：由 `scripts/governance/check-coverage.mjs` 承载（release / regression-weekly 调用，阈值 statements 90 / branches 80 / functions 90 / lines 90）；本批未改动脚本与阈值，`pnpm check:coverage` 实跑通过。
4. 本地 `node_modules/.pnpm` 可能残留 vitest 4 的虚拟目录；解析面唯一性以 `pnpm ls vitest` / `node_modules/.bin/vitest --version` / lockfile 无 `vitest@4` 判别（清理整目录受仓库安全红线约束，未执行）。
5. 浏览器模式 / benchmark / 多项目配置均未使用，相关迁移项按上表判定为不适用。
