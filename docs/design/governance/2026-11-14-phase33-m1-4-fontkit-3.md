## 1. 变更

| 项 | 内容 |
|:---|:---|
| `fontkit` | `2.0.4` → **`3.0.0`**（`^3.0.0`，ESM-only） |
| `@types/fontkit` | 保持 `^2.0.9`（fontkit 3 未内置类型；实际使用面仅 `openSync` / `hasGlyphForCodePoint`，`vue-tsc` 通过） |
| 调用面 | 唯一调用方 `test/visual/font-coverage.ts`，**零改动** |

## 2. ESM-only 适配核对

- 调用方本就使用 `await import('fontkit')` 动态导入，不依赖 CJS `require`；升级后模块解析正常。
- 实测 `import('fontkit')` 暴露 `openSync` / `open` / `create`；`openSync('test/e2e/fixtures/fonts/caomei-test-latin.woff2')` 返回字体对象，`hasGlyphForCodePoint(0x41)` 为 `true`（woff2 子集可读）。
- `fontkit/package.json` 不再被 `exports` 暴露（`require('fontkit/package.json')` 会 `ERR_PACKAGE_PATH_NOT_EXPORTED`），仓内无此类访问。

## 4. 边界

1. 6 项失败为登记时点既有的字体族基线问题（字体解析环境差异），**非本次升级引入**；本批不重冻结视觉基线（重冻结须按测试规范在 CI 同环境执行）。
2. `@types/fontkit@2.0.9` 与 v3 的 API 子集兼容；若后续使用 v3 新增 API，需确认类型来源（v3 未内置 `.d.ts`）。
3. 官方 registry 安装会下载 `dfa@2.0.0` 等传递依赖；lockfile 只记录 integrity、不记录 registry 地址（过程记录不可事后复算）。本轮已核对 `fontkit@3.0.0` / `dfa@2.0.0` 的 sha512 与官方源一致；CI 使用默认源安装不受影响。
4. 调用面之外无 `fontkit` 引用：`rg "fontkit" src test scripts`（2026-11-14）仅命中 `test/visual/font-coverage.ts`；`package.json` 只有 `fontkit` 与 `@types/fontkit` 两行声明（该命令的 scope 不含 `package.json`）。
5. `unicode-trie@3.0.0` 声明 `node >= 20.17.0`（`fontkit@3.0.0` 自身无 engines）；本仓 `engines.node >= 22`、CI `lts/*` 均满足，未来下调下限时须复核。
