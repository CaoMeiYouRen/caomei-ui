# Phase 34 M2-1：嵌套遮罩层级评估（固定档位 vs per-instance 层级栈）

> 创建时间：2026-11-15
> 触发：用户「按照合适的顺序推进当前阶段的待办」。范围与验收口径见 [Phase 34 登记批次](./2026-11-14-phase34-registration.md) §2 的 M2-1 行；问题来源见[遮罩类组件协作问题调研](./2026-11-14-overlay-collaboration-research.md) §4.1 第 1 条。
> 性质：**只评估**——零代码、零 token 改动（`git status` 中无 `src/**` / `test/**` 变更）。

## 1. 结论

**维持固定档位（`overlay 1000` / `content 1001`），不实现 per-instance 层级栈。** 实测到两类异常：① **视觉**：嵌套模态时子层遮罩不压暗父层内容（父层看起来仍「活跃」，实际已被遮罩拦截）；② **视觉 + 交互副作用**：父层已打开的浮层面板（`dropdown 1050`）高于子模态内容（`1001`）且保持可见，但被 `body` 的 `pointer-events: none` 一并置为不可点；点击该可见区域会**先按「外部点击」关闭子模态、再落到随后暴露的面板选项**（实测一次点击同时完成两件事）。关闭顺序、焦点隔离、滚动锁与父内容的命中拦截均正确。实现完整层级栈需要改造浮层档位派生、若干个浮层组件与两套回归装置，成本与收益不匹配，转为**带触发条件的候选**（见 §6）。

若未来触发实现，推荐**方案 B2「模态 base + 浮层档位派生」**（§3 / §5），不推荐仅抬高模态 content 的 B1。

## 2. 现状与实测

### 2.1 结构事实

| 面 | 事实 |
|:---|:---|
| 档位 | `--caomei-z-overlay: 1000` < `--caomei-z-modal: 1001` < `--caomei-z-dropdown: 1050` < `--caomei-z-tooltip: 1060` < `--caomei-z-toast: 1100`（`src/styles/theme.css`） |
| 分配方式 | Dialog / Drawer / ConfirmDialog 三者的遮罩与内容**固定取档位**，无实例计数 |
| 相等档位 | 第二层内容与父层内容同为 `1001`，靠 **portal 的 DOM 顺序**（后挂载者在上）取胜 |
| 遮罩使命 | 遮罩拦截指针（`pointer-events` 由 Reka 的 `DismissableLayer` 与 owner 锁承担），视觉上压暗被遮挡区域 |

### 2.2 真实 Chromium 实测（父层 Dialog 内再开一层 Dialog）

| 观测 | 结果 |
|:---|:---|
| 计算 `z-index` | 父遮罩 `1000` / 父内容 `1001` / 子遮罩 `1000` / 子内容 `1001` |
| 子遮罩是否压暗父内容 | **否**：父内容两侧在截图中保持原亮度，只有父层之外的页面区域被压暗（子遮罩 `1000` < 父内容 `1001`） |
| 父内容能否被点击 | 否：父内容 `pointer-events: none`，命中测试落在子层遮罩上——**看起来活跃、实际被拦截**，视觉与交互不一致 |
| 父层可访问性 | 父内容 `aria-hidden="true"`；读屏只暴露子层（正确） |
| 关闭顺序 | 第一次 Esc 关子层（层数 2 → 1），第二次关父层（1 → 0）；每次只关最上层（正确） |
| 滚动锁 / 指针锁 | 两层共享锁：关子层后 `body` 仍 `overflow: hidden` + `pointer-events: none`；关父层后恢复 `visible` / `auto`（正确） |
| 焦点 | 子层打开后自动聚焦其关闭按钮；父层内容不可达（正确） |
| 父层浮层面板 | 父层 Select 面板保持 `z-index 1050`、`visibility: visible`，高于子模态内容 `1001`；其计算 `pointer-events` 为 `none`（继承自 `body` 的 modal 锁），命中测试落在子层遮罩上——**可见但不可点** |
| 面板区域的点击后果 | 在面板选项位置真实点击一次：子模态关闭（外部点击），随后该次点击落到已暴露的面板并选中选项——一次点击触发两个动作 |

> 取证方式：一次性 Chromium 探针（父层 Dialog → 打开父层 Select → 程序化打开子 Dialog），读数与截图由调用方采集，探针不随仓库提交；长期结论以本节为准。父层 Select 面板读数：`z-index 1050`、`visibility: visible`、`pointer-events: none`（`body` 同为 `none`），命中测试返回 `caomei-dialog__overlay`；真实点击面板选项位置后子模态关闭并落下选中。

结论（逐项）：关闭顺序、焦点隔离、滚动锁、父内容命中拦截均**已正确**；异常为 ① 视觉压暗缺失（子层遮罩不压暗父层内容）、② 视觉重叠 + 点击穿透副作用（父层面板可见但不可点，点击该区域先关子模态再落下选中）。**不对整体作归属断言**。另：「相等档位靠 DOM 顺序」是隐式契约——一旦 portal 顺序变化（如重新挂载、并列渲染顺序调整），层叠结果会静默改变。

## 3. 候选方案

| 方案 | 做法 | 成本 | 风险 |
|:---|:---|:---|:---|
| **A 固定档位（采用）** | 维持现状；把「嵌套遮罩不压暗父层」记为已知取舍 | 0 | 视觉不一致；相等档位依赖 DOM 顺序 |
| **B1 仅模态基数** | 每个模态实例分配 `base`（`1001 + 2n`）：遮罩 `base - 1`、内容 `base` | 中（3 个模态组件 + 文档） | 同一阈值缺陷：深度 ≥ 21 时 `base + 59 > 1100`，`dropdown` / `tooltip` 会被固定最高的 Toast 反超，子层内面板同样落到内容之下 |
| **B2 模态基数 + 浮层派生（若实现即选此）** | 模态实例分配 `base` 并通过 context 传给同树的**锚定浮层**子组件；浮层 `z-index = base + 档位偏移`（dropdown +49 / tooltip +59）；**Toast 固定 1100、Image 预览 = toast + 1 不参与派生** | 高（模态 3 + 锚定浮层 8 + 检查脚本 + 两套回归） | **子模态基数必须高于父层栈的最高可能档位**（父 `base + 59`），否则父层面板仍盖住子模态；该约束与固定最高的 Toast（1100）冲突：父 `base` 1001 + 59 → 子 `base` 至少 1061，**深度 1 时子层面板即达 1110 / 1120，已反超固定 Toast 1100**（与 B1 判据同一标准），要保住 Toast 最高必须同时把 Toast / Image 改为派生，或显式接受「子层面板可覆盖 Toast」。另有 z-index 膨胀、SSR 客户端分配、与宿主第三方浮层竞争 |

**共同约束**：无论 B1 / B2，基数都只能在客户端分配（打开时），内联样式不参与 SSR，避免水合不一致；且必须给基数设上限与回收策略，防止长会话内单调增长。

## 4. 影响面清单（若实现 B2）

| 面 | 影响 |
|:---|:---|
| Token 语义 | `--caomei-z-*` 从「固定档位」变为「基础档位 + 偏移」；组件内已存在的 `--caomei-<comp>-z-index` 覆盖钩子**可能被运行时内联值取代**——下游 `style="z-index: …"` 与覆盖钩子的优先级、语义都会变化，需按可行性评估是否计为 breaking 并写迁移说明 |
| `check:overlay-z-index` | T1（档位自证）/ T2（遮罩专用）/ T3（模态内容在册）/ T4（浮层高于模态）/ T5（覆盖钩子形态）/ T6（静态变体不得继承档位）/ **T7（抗收窄）** / **T8（未识别形态 fail-closed）** / **T9（允许名单反向校验）** / T10（E2E 清单联动）逐项复核：静态数值比较改为「基础顺序 + 动态值来源」；**T8 是主要风险**——若基础 token 不沿用 `--caomei-z-*` 前缀，`parseZIndexValue` 的两种 `var()` 形态都识别不了，T2 / T4 / T5 / T6 会同时被绕过，必须扩面并补负向对照（写坏派生值须判失败） |
| 模态组件 | Dialog / Drawer / ConfirmDialog 分配并下发 `base`；子层基数需高于父层最高档位（见 §3 B2 约束），`useConfirm` 的确认框同样走栈 |
| Toast / Image | 若要让嵌套深度 > 1，必须把固定 `1100` 的 Toast（及 `toast + 1` 的 Image 预览）也纳入派生或重定基数；本阶段不改 |
| 锚定浮层（8 个） | Select / MultiSelect / AutoComplete / Popover / DropdownMenu / Tooltip / ColorPicker / DatePicker 读取 context 并派生自身层级（与 `test/e2e/fixtures/overlay-panels.json` 的 8 项清单一致） |
| 固定档位例外（2 个） | **Toast** 固定 `1100`；**Image 预览** 固定 `toast + 1`（`calc(var(--caomei-image-preview-z-index, var(--caomei-z-toast)) + 1)`）——两者都**不参与** base 派生，`check-overlay-z-index` 的 `NON_PANEL_FLOATING_COMPONENTS` 同步 |
| E2E | `overlay-stacking` 的固定期望改为相对关系（子层 > 父层）；`overlay-collaboration` 的 C6 增加「子层遮罩压暗父层」断言与负向对照（**C6 由 M2-3 落地**）；新增嵌套三层用例 |
| 视觉基线 | 单层快照不受影响（首层 base 仍为 1001）；嵌套场景当前无基线，需新增 1 ~ 2 张；`capture:styles` 需重冻结并核对 0 差异 |
| a11y | 结构不变（父层 `aria-hidden` + 子层 `aria-modal`）；需在组件页说明双层 `aria-modal` 的含义 |
| SSR / 水合 | 基数客户端分配；文档站 `ssg` 示例（Dialog 默认关闭）不受影响 |
| 文档 | [设计规范](../design-spec.md) §2.5「层级 / 图标 token」、Tooltip / Dialog / Drawer / Popover 等页面、`docs/design/components.md` 能力清单 |

## 5. 若实现的条目草案（待授权，不占编号）

- **范围**：模态层级栈（Dialog / Drawer / ConfirmDialog）+ 浮层档位派生（约 8 个浮层组件），token 由固定档位改为「基础 + 偏移」，同步更新 `check:overlay-z-index` 与两套回归装置。
- **文件面估算**：≈ 24 ~ 26（模态 3 + 锚定浮层 8 + 共享栈 1 + 检查脚本 1 + 单测 4 ~ 6 + E2E 2 + 视觉 1 + 文档 4；Toast / Image 预览不参与派生，不改源码；分项之和与总区间一致）。按[规划规范 §5](../../standards/planning.md) 拆 3 个原子条目（模态栈 / 浮层派生 / 装置与文档）。
- **与 M2-3 的关系**：本条结论为「维持固定档位」→ M2-3（C6 嵌套用例）按**现状**断言、不得假定 z-index 递增，并把「子层遮罩不压暗父层」记为现状契约。
- **验收口径**：嵌套第二层的遮罩压暗父层内容（像素 / 计算样式双证）；子层内 Select 面板仍高于当前模态；单层视觉基线 0 差异；父层 `aria-hidden`、Esc 只关最上层、滚动锁与指针锁成对释放；`check:overlay-z-index` 覆盖动态值来源；无 SSR 水合告警。
- **风险**：与宿主第三方浮层的层级竞争（需文档给出上限与覆盖钩子）；长会话基数增长（需回收）；检查脚本从静态变动态后判别力下降（需负向对照）。

## 6. 触发条件

满足任一即重新评估并进入 Backlog：

1. 下游出现「嵌套模态需压暗父层」或「父层浮层面板盖住子模态 / 点击可见面板导致误操作」的真实反馈（截图 / 设计评审 / 用户反馈）；
2. 出现相等档位依赖 DOM 顺序导致的**非视觉**缺陷（遮挡命中、层叠错序、关闭错层）；
3. 新增**需要与 Dialog / Drawer / ConfirmDialog 共享栈**的模态（如 Sheet / 全屏编辑面板）；既有 Image 预览灯箱属全视口覆盖、按 `toast + 1` 固定处置，不计入本条件。

在此之前：在 Dialog / Drawer 组件页登记「嵌套时子层遮罩不压暗父层、父层面板可见但不可点且点击会穿透」为已知取舍，避免被当作缺陷重复上报。
