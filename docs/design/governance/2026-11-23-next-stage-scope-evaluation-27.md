## 4. 推荐组合与决策点

**推荐核心**：**M1 + M2 + M3**（发布收口 + 真机验收 + 治理收尾，3 主线 / 8 条）。理由：

- **M1 是自然收口**：`v1.4.0` 后已积压 8 个 `feat`，Phase 41 的新能力（Form 校验、月 / 年、NavBar）尚未进入下游；周回归最近 success 为 `7ee8f7c`，距 `8038ab40` 已 32 个提交，发布前必须在 HEAD 重跑。
- **M2 是 Phase 41 唯一未闭环的验收面**：真机三项已有清单与替代证据，缺的只是设备执行；纳入阶段可避免长期悬空，但**依赖用户条件**。
- **M3 成本低、收益确定**：三项均为一到两个文件的治理 / 文档改动，且直接来自 Phase 41 的复盘发现（验证集缺口、§3 登记缺口、landmark 提示）。
- **M4 / M5 均无新的下游证据**：P2 组件与二期语言维持候选，避免无需求驱动的广度扩张。

### 决策点

- **D0 阶段取向**：
  ① **推荐：M1 + M2 + M3**（3 主线 / 8 条；M2 依赖真机条件；若 D3 ② 则追加 Statistic → 4 主线 / 10 条）
  ② **M1 + M3**（2 主线 / 6 条；暂不做真机验收，M2 留 Backlog；不含 M4，D3 固定为 ①）
