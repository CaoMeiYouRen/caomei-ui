# Backlog 优先级双轴评估（重要度 × 紧急度）

> 创建时间：2026-11-25
> 触发：用户裁定「单一优先级无法区分紧急与重要」，要求对 Backlog 每条给出**重要度 1–5** 与**紧急度 1–5** 双轴评分，并按「重要且紧急先做 / 重要不紧急排期 / 不重要但紧急快速评估 / 其余延后」排期；同时明确项目处于**快速开发期**，在没有更高优先的安全修复时以**新组件 / 新功能**为主。
> 性质：**评分批次记录**；评分口径的单一事实源是[规划规范 §3.1](../../standards/planning.md#_3-1-优先级双轴评估与排期-2026-11-25-用户裁定)，逐条分数落在 [`backlog.md` §1](../../plan/backlog.md) 的「重要 / 紧急 / 建议」三列。

## 1. 评分口径（摘要）

- **重要度**：5 = 安全 / 数据正确性 / 阻断下游构建发布 / 已确认功能缺陷；4 = 有真实下游证据的能力或体验缺口，或用户明确指定的当前阶段方向（如快速开发期的新组件）；3 = 质量或一致性收益明确但有替代；2 = 已有等价替代；1 = 可选增强。
- **紧急度**：5 = 安全告警、已确认回归、发布阻断；4 = 有明确时间窗（含发布窗口）；3 = 下游正在等待或 workaround 已产生成本（受上游阻塞的安全项亦落此档并要求写明解禁触发）；2 = 条件触发接近命中 / 按节奏推进无硬时点；1 = 无时间压力。
- **象限**：重要 ≥4 且紧急 ≥4 → 首排；重要 ≥4 且紧急 ≤3 → 排期；重要 ≤3 且紧急 ≥4 → 快速评估（不做即移入 §3）；其余 → 延后。象限只决定顺序，**不构成进入 `todo.md` 的授权**。
- **方向分不等于「点名最高」**：用户给出的方向（快速开发期以新组件为主）按字面覆盖 §1.11 全组，七条同取 4 / 2，**不由本批在组内挑出少数条抬分**；组内先做哪一条留待阶段登记时按用户选择。
- **阶段取向**：快速开发期，同等分数下新组件 / 新功能优先；缺陷、测试覆盖率、文档治理默认不抢占新功能排期（安全与已确认回归除外）。进入维护期或用户改判时本条失效。
- **安全项处置**：仅「可当期处置的安全告警 → 5 / 5」称**抢占**排期；受上游阻塞、当期无可行修复 → 5 / 3 入排期，并写明阻塞点与解禁触发。

## 2. 评分结果（38 条）

| 象限 | 条目 |
|:---|:---|
| 首排 | `1.5.0` 发布收口（5 / 4；紧急 4 来自发布窗口，用户裁定 2026-11-29 之前不列入规划，窗口到达后立即首排） |
| 排期 | 版本升级影响面评估自动化（4 / 3）、三家下游 1.4.0 适配回收（4 / 2，依赖发布）、`glob` 跨 major 覆盖（5 / 3，受上游阻塞、无当期可行修复），以及 **§1.11 全部 7 条新组件**（4 / 2，用户指定的快速开发期方向） |
| 快速评估 | 无（出现「不重要但紧急」项时一轮取证内决定去留） |
| 延后 | 其余 27 条 |

- **新功能主线的排序结论**：§1.11 七条同为「排期」档（重要 4 = 用户指定的快速开发期方向；紧急 2 = 无硬时点，按节奏推进），是下一阶段（非发布）新功能批次的候选池；组内先做哪一条在阶段登记时由用户选定，本批不做组内抬分。
- **发布收口的特殊性**：它是唯一「首排」项，但用户在 2026-11-25 明确「2026-11-29 之前不列入规划」，因此其排期事实由窗口而非分数决定——**分数只定义窗口到达后的顺序**。

## 3. 与既有载体的关系

- `backlog.md`：§1 全部表列由「优先级」改为「重要 / 紧急 / 建议」；§1.11 增「象限提示（快速开发期）」；§2 维护约定改引规划规范 §3.1；条目数不变（38）。
- `planning.md`：新增 §3.1（评分锚点、象限动作、阶段取向、安全项处置、载体口径）。
- `todo.md`：仍为「当前无进行中阶段」；本轮**不登记阶段**（用户上一轮撤销了规划）。阶段登记时按象限排序，不再另设优先级字段。

## 4. 边界与复评

- 评分为**当期判断**，不是契约：下游证据、时间窗或安全状况变化时同批更新分数与建议；**每季度**或每次阶段登记前复核一次。
- 分数与象限无机检守卫（自然语言判断），由 Review Gate 抽查「分数与说明依据是否相符」。

## 5. Review Gate

- **R1**（standard / ≤10 分钟）：**Reject**，blocker 2 / warning 5 / suggest 4 —— 无下游证据的 4 分（`Tour` / ContextMenu）、`glob` 安全条与安全条款冲突，另含索引规模计数、载体指针等。
- **R2**（quick delta / ≤5 分钟）：**Reject**，blocker 2 —— 「用户方向」锚点在组内被选择性抬分（与「不默认最高优先级」冲突）、`backlog` §1.11 提示与表内不一致；另 5 项 follow-up。
- **R3**（quick delta / ≤5 分钟）：**Pass**，blocker 0 —— 复核复算分布（38 = 首排 1 / 排期 10 / 快速评估 0 / 延后 27）、分数—建议零不符、`glob` 5 / 3 与「安全项处置」一致、索引无规模计数；另给 4 项提交前必须项（行内文案与本节回填），已同批收口。
