# 移动端就绪矩阵

> 面向使用方与维护者：逐个公开组件页列出 320 / 390 / 768 三档形态、降级策略与已知边界。**行为口径的单一事实源**是[响应式设计 §3](../design/responsive.md)，本页只做**逐页映射与缺口登记**，不重述条款。

## 生成口径

- 行 = `docs/components/` 下的全部组件页（**72 行**，不含总览 `index`、`composables`、`icons`、`locale`、`showcase`）。
- 数据来源 = **§3 行为模式登记 + 组件源码核对**；未单独实测的项在「已知边界」列显式标注，不写成实测结论。
- 三档视口：320（sm 档内部点）/ 390（移动矩阵档）/ 768（平板矩阵档）；桌面（≥1024）只在该行有差异时标注。
- 分类计数：**56 行**有 §3 登记的模式（依据列给模式号）、**16 行**无专属规则（随容器收敛）；原 7 行「源码有规则、§3 未登记」已于 2026-11-23 补登到 §3 #22 ~ #26。Toast 的高度上限（`100vh` / `100dvh`）与 Image 预览层的 `90vw` / `90vh` 不构成独立行为模式（其余视口相对尺寸已登记为 #1 / #2 / #20），随[移动端与响应式](./mobile.md)的 `dvh` 口径与安全区 token 处理。
- 与登记估算的口径差异：登记按「页面级移动说明」估算 30 + 41 = 71；本表按「§3 模式 + 源码核对」逐页落位，总数 72（NavBar 为 Phase 41 新增的第 72 页）。两种口径不是同一集合，差异说明见文末。

## 已知缺口与使用建议

- 16 行「随容器收敛」的组件没有专属窄屏规则：窄屏下是否可读取决于使用方容器宽度，建议在 320 档自测关键页。
- 原 7 行「源码有规则、§3 未登记」的登记缺口已于 2026-11-23 补登到 §3：`transfer`（#22）、`popover` / `popconfirm` / `tooltip`（#23）、`cascader`（#24）、`time-picker`（#25）、`descriptions`（#26），依据列已改指模式号；此后新增组件页须同步本表，并在该组件有专属行为时补 §3。
- 明确的设计内滚动：ButtonGroup / SplitButton / Tabs / DataTable（容器横向滚动，成员不裁切）。
- 明确的使用方职责：DataTable 卡片化、Dialog 全屏、Stepper 方向转换、超长选项宽度。
- 触摸目标（§3 #16）覆盖的清除 / 关闭按钮与表单控件盒已在对应行标注 #16；未标注的组件不在该模式范围内。

## 口径说明

- 登记估算（30 / 41）统计的是**组件页正文里写了移动说明**的页面；本表的分类统计的是**§3 模式登记 + 源码规则**。同一组件可能「§3 有模式但页面未写说明」，也可能「页面有零散提示但 §3 未登记模式」，两者不是同一集合，故总数不同。
- 新增组件页时需同步本表（行数 +1）与 §3（若有专属行为）；本表暂无机检守卫，行集合可用脚本对账（`docs/components/*.md` 去 5 个非组件页）。
