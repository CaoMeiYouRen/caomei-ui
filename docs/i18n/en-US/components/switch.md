# Switch

A switch toggles a single option on or off; it wraps Reka UI Switch.

## Basic usage

Two-way bind the state (`boolean`) with `v-model`. When there is no visible label, provide an accessible name via `label`.

/>

## States

`disabled` disables the switch; the on/off state is determined by `modelValue`.

## Form integration

With `name`, the switch is submitted with a native form when inside `<form>`; `value` is the submitted value (defaults to `'on'`), and `required` participates in native validation.

```vue
<form>
  <CaomeiSwitch v-model="notify" name="notify" value="yes" required label="Push notifications" />
  <button type="submit">Submit</button>
</form>
```

## Events

- `update:modelValue`: used with `v-model`; the parent drives the value.
- `change`: emitted **only on user interaction** (click / keyboard toggle) with the new boolean value; a programmatic `modelValue` change from the parent does not emit it.

> PrimeVue passes the native event object as the `change` payload, whereas this library passes the boolean directly; downstream code that just refreshes on change (without reading the payload) can migrate as-is.

## Accessibility

- The control is rendered by Reka UI as a button with `role="switch"`; `aria-checked` outputs `true` / `false`, with keyboard focus and toggling.
- `required` maps to `aria-required`.
- When there is no visible label, use `label` for the accessible name (mapped to `aria-label`); you can also associate an external `<label :for="id">`, and Reka reads that label's text to derive the accessible name when `aria-label` is missing.
- `id` is only used to associate an external label and is not auto-generated (unlike Checkbox, where `id` is auto-generated by default).
- When both visible text and `label` are provided, `label` should contain or equal the visible text to avoid a mismatch between the accessible name and the visible label (WCAG 2.5.3).
- Keyboard focus shows a `:focus-visible` ring and respects `prefers-reduced-motion`.

## Style customization

Styles are based on CSS variables and kept low-specificity for easy overriding:

| Variable | Default | Description |
|------|------|------|
| `--caomei-switch-width` | `40px` | Track width |
| `--caomei-switch-height` | `22px` | Track height |
| `--caomei-switch-radius` | `999px` | Track radius |
| `--caomei-switch-bg` | `--caomei-color-border` | Track background when off |
| `--caomei-switch-border` | `--caomei-color-border` | Track border when off |
| `--caomei-switch-active-bg` | `--caomei-color-primary` | Track background and border when on |
| `--caomei-switch-thumb-size` | `16px` | Thumb size |
| `--caomei-switch-thumb-bg` | `--caomei-color-bg` | Thumb background |
| `--caomei-switch-thumb-travel` | `18px` | Horizontal thumb travel when on |

> When overriding `--caomei-switch-width` / `--caomei-switch-height`, adjust `--caomei-switch-thumb-size` and `--caomei-switch-thumb-travel` together to keep them aligned.

```css
.caomei-switch {
    --caomei-switch-active-bg: #16a34a;
    --caomei-switch-width: 48px;
    --caomei-switch-thumb-travel: 26px;
}
```
