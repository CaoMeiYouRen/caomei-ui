# 规划规范

本文档定义 caomei-ui 的规划制度，包括 `backlog` / `roadmap` / `todo` 三层结构与新需求准入流程。

## 1. 规划载体

| 载体 | 文件 | 职责 |
|------|------|------|
| 路线图 | [roadmap.md](../plan/roadmap.md) | 长期阶段规划与里程碑（阶段表只登记已授权阶段），记录已完成阶段摘要 |
| 待办事项 | [todo.md](../plan/todo.md) | 当前阶段的原子条目与验收状态 |
| Backlog | [backlog.md](../plan/backlog.md) | 已评估候选池与长期主线，等待用户决策 |
| 待办归档 | [todo-archive.md](../plan/todo-archive.md) | 已完成阶段的归档记录 |

## 2. 三层结构与流转

```
新需求 → 评估 → backlog.md → 用户决策 → todo.md 当前阶段 → 实施 → 归档到 todo-archive.md
                                      ↓
                                  roadmap.md 阶段摘要
```

## 3. 新需求处理原则（hard requirement）

1. **默认路径**：新需求（功能 / 重构 / 体验优化 / 集成 / 监控等）先**评估**，再进入 `backlog.md`，等待用户明确决策是否进入当前阶段。
2. **不自动升级**：未经用户明确授权，backlog 候选**不得**进入 `todo.md` 当前阶段；候选条目**不包含**阶段编号。
3. **不擅自规划下一阶段**：阶段归档后，下一阶段范围（包括 `roadmap.md` 已列出的内容）在未经需求评估与用户明确决策前，**不得**登记为 `todo.md` 当前阶段待办；`todo.md` 仅承载已获授权启动的阶段条目，其阶段衔接规则只引用本规范，不自行重述。
4. **不默认最高优先级**：阶段内条目组合由用户决策，AI 不得推断某条应作为最高优先级并默认启动。
5. **插队例外清单（仅以下三类可直接进入 todo）**：
   - 已确认的安全漏洞（依赖 CVE / 供应链告警）；
   - 破坏下游项目构建或发布的兼容性问题；
   - 直接影响可用性的 blocker 级缺陷。
6. **合规核验**：本原则由 `@code-reviewer` 在治理审计中强制检查，违规即 Reject。
7. **范围降级同样须用户裁定**：已授权条目内的零用量子能力不自动升降级——先取证（用量统计 + 快照日期），再交用户决策；决策后才从 `todo.md` 移入 `backlog.md`，并在条目说明保留移出理由与触发条件。

## 4. 阶段与条目命名

- 阶段：`Phase N`（如 `Phase 0 立项与 POC`），不使用无意义的递增数字堆叠。
- 原子条目：一个条目对应一个可独立验收、可独立提交的逻辑变更。
- **禁止**在代码注释与测试名中写入规划编号（如 `T001`、`P1-1`）；例外仅真实常量与带文档路径的导航指针。
- **阶段编号只在授权启动时分配**：编号取「已有最大编号 + 1」，且仅授予经用户明确授权启动的阶段。**未经授权不得为「将来可能做」的工作预留编号**，也不得把未授权的范围提前登记为独立阶段——未授权工作的候选一律留在 [Backlog](../plan/backlog.md)，不进入 [路线图](../plan/roadmap.md) 阶段表；未规划过的条目**不获得阶段编号**。目的：编号随时间单调递增，避免插入 / 延后 / 取消导致的编号错乱。编号分配合规由 `@code-reviewer` 在治理审计中检查。
- 已授权阶段内部的「第一阶段 / 第二阶段」分段**不属于新增阶段编号**；分段范围仍须在启动前单独评估并登记。
- [路线图](../plan/roadmap.md) 中标注为历史预留的编号保留原编号，但**不再新增此类预留**；预留编号的归属与说明以路线图为准。

## 5. 任务粒度约束

- 单个原子条目建议不超过 **10 个文件 / 800 行新增**。
- 生成物（如 `pnpm-lock.yaml`、构建产物）不计入上述文件数与行数阈值，但必须与触发其变更的声明同提交，并在提交信息中说明生成来源。
- 超阈值时必须拆分为多个条目；未拆分且无正当理由的改动，`@code-reviewer` 有权 Reject。
- 含多项能力的条目按真实用量分批交付（有下游用量先做、零用量待用户决策）；用量取证须记录命令与快照日期，避免与相邻条目的统计串号。

## 6. 阶段容量

- 每个阶段聚焦 **3–6 条主线**，避免一个阶段承载过多不相关内容。
- 每条主线必须写明：执行范围、非目标、最小验收标准。

## 7. 状态同步

- 开发前：对齐 `roadmap.md` 与 `todo.md`。
- 开发后：同步更新 `todo.md` 状态与验收结果，阶段完成后迁入 `todo-archive.md`。
- 阶段归档时检查 `.session/wisdom.md` 活跃条目：达到阈值（>= 20）则执行蒸馏（`pnpm distill:wisdom --check`，详见 [Session Wisdom 蒸馏机制](../design/governance/session-wisdom-distillation.md)）。
- 禁止「代码完成但规划未同步」。
